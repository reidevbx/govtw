# P3 元件決定表（2026-10-14）

P3 共 2 個新元件。使用者確認後依序連續執行，不再逐項詢問。

- 來源：各任務文件的「待確認」段，加上實作前檢查程式碼發現的問題（標「新增」）
- 每項附建議做法；使用者只需改不同意的項目
- 沿用 [P0](./2026-10-14-p0-decisions.md)、[P1](./2026-10-14-p1-decisions.md)、[P2](./2026-10-14-p2-decisions.md) 決定表的共通決定

## 一次性驗證碼 OTP Input

| # | 問題 | 建議 |
|---|---|---|
| OT1 | 直接用 text-input 加文件範例，還是另做元件 | **另做元件**。text-input 已有 `inputmode`、`autocomplete`、`width`，輸入框本身不缺功能；缺的是「重新傳送」按鈕與倒數。倒數的宣告規則容易寫錯，所以包成元件 |
| OT2 | **新增**：繼承 text-input 還是獨立元件 | **獨立元件**，理由同 PW1（text-input 的狀態欄位都是 `private`）。token 用 `--govtw-otp-input-*` |
| OT3 | **新增**：中文名稱 | 改為「**一次性驗證碼**」，不叫「簡訊驗證碼」。Email 寄送的驗證碼也適用。與 captcha 的「圖形驗證碼」區分 |
| OT4 | **新增**：輸入框固定設定 | `inputmode="numeric"`、`autocomplete="one-time-code"`、`spellcheck="false"`、寬度同 text-input `width="10"`。`label` 預設「驗證碼」 |
| OT5 | **新增**：是否限制長度、輸滿自動送出 | **都不做**。不設 `maxlength`，使用者貼上含空格的驗證碼時才不會被截斷；文件寫明由伺服器去除空格。輸滿自動送出違反 WCAG 3.2.2（輸入時不可自動改變情境） |
| OT6 | **新增**：重新傳送的 API | `resend-delay` 屬性（秒，預設 60）。元件載入時開始倒數；按下「重新傳送驗證碼」發出 `govtw-resend` 事件並重新倒數。元件不自己呼叫 API，由作者處理 |
| OT7 | **新增**：倒數期間的按鈕 | 按鈕一直顯示，倒數期間設 `aria-disabled="true"` 並忽略點擊，不用 `disabled`。`disabled` 會讓按鈕無法聚焦，按下後焦點會遺失 |
| OT8 | **新增**：倒數文字與宣告 | 按鈕旁顯示「60 秒後可重新傳送」，每秒更新但**不放在 live region**。倒數結束時 live region 念一次「現在可以重新傳送驗證碼」 |
| OT9 | **新增**：傳送到哪支電話、有效期限 | 都由作者寫在 `hint`，例如「已傳送到 0912-xxx-678，10 分鐘內有效」。元件不倒數有效期限 |

## 頁內目錄 Contents List

| # | 問題 | 建議 |
|---|---|---|
| CL1 | **新增**：作者寫清單，還是元件自動抓頁面標題 | **作者寫 `<ol>`／`<ul>` 加 `<a href="#id">`**，元件用 light DOM 包裝（依 C6）。自動抓標題要猜選擇器，且標題沒有 `id` 時連結會失效 |
| CL2 | 中文編號（一、二、三）怎麼做 | **作者把編號寫在連結文字裡**，與頁面標題的文字一致（如「一、計畫緣起」）。元件不加清單符號。用 CSS 的中文編號，標題文字與目錄文字會不一致 |
| CL3 | **新增**：標題與 `<nav>` 名稱 | `heading` 屬性預設「目錄」，元件產生可見的 `<h2>`，`<nav>` 用 `aria-labelledby` 指向它 |
| CL4 | **新增**：巢狀層級 | 支援 2 層（如 h2 底下的 h3），第 2 層縮排。文件建議不超過 2 層 |
| CL5 | **新增**：捲動時標示目前段落、固定在畫面上 | **第一版都不做**。只做靜態目錄 |
| CL6 | **新增**：與 side-navigation 的分工 | 頁內目錄連到同一頁的標題；side-navigation 連到同單元的其他頁。兩頁文件互相連結 |
| CL7 | **新增**：完成後 | 不改其他元件。「回到頁首」連結不在本次範圍 |
